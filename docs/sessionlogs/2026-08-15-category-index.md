# 2026-08-15 — Phase 2: generated category index

Task: "build a better dashboard/index. i want lists by category."

Target: `paprika-export/index.html`, which Paprika exports as a flat alphabetical
`<ul>` of 247 links. Generated by the workflow, not hand-written — a hand-maintained
index would go stale on the next export.

## Design, and why

**The complete A-Z list leads; categories are a way in, not the organising
principle.** With 52% of the library carrying no category, a category-only index would
hide more than half of it. The page states the uncategorised count in its header
rather than letting it disappear, and gives those 129 recipes their own section.

**Each multi-category recipe appears in every list it belongs to**, with its other
categories shown as inline chips, so a recipe found under Swiss also shows that it is
`_Proven` and `Fall/Winter`.

**Curation tags come first, in their own "Collections" section**, visually separated
from the 29 cuisine/type categories, with `_Proven` open by default. They are labelled
verbatim, underscore included — that is Max's notation and he will recognise it.

**Categories are ordered by size, largest first**, so the long tail (6 categories hold
a single recipe) sinks to the bottom.

**Text-only, no thumbnails.** The 288 photos average 134 KB; a thumbnail grid would be
a ~31 MB page and would undo phase 1. The generated page is 145 KB uncompressed.

**Native `<details>` for each category** — collapsible with no JavaScript. The filter
box is progressive enhancement: with JS off, every recipe is still listed and linked.
Filtering matches name *and* category, so typing "swiss" works from the flat list too.

- filter by name ("aquafaba" → 3), by category ("swiss" → 11), no match →
  "Nothing matches that." with every block hidden
- clearing the filter restores all 662 items and unhides every block

- no console errors, no failed requests

New fail-loudly check in `verify-site.ts`: every recipe page must be linked from the
generated index, comparing percent-decoded hrefs against the file set. Without it, a
parser regression could ship an index listing half the library and still pass.

## Notes

`build-index.ts` decodes only the five entities Paprika actually emits (`&apos;`
`&amp;` `&quot;` `&gt;` `&lt;` — 6 recipe names use them) and re-escapes on output.
Hrefs are percent-encoded per filename, which matters for the 30 non-ASCII names, the
5 containing `&`, the 4 with double spaces, and the U+200E bidi marks in
`Grilled Eggplant Salad (‎חצילים ‎סלט).html`.

Recipe sorting uses `Intl.Collator`, so `Älplermagronen` sorts between `Aloo Jeera`
and `Apple Pie` rather than after `Z`.
